## 1. 目标与职责边界

### 1.1 要解决的问题

OCR 出来的中文数学 Markdown 有两类问题，必须分开处理：

| 类别 | 例子 | 谁来处理 |
| --- | --- | --- |
| **格式问题**（可机械判定） | 全角标点、裸变量没进公式、该加的 `\displaystyle`、编号被包进公式 | 规范化器 |
| **内容问题**（无唯一解） | OCR 认错符号、公式缺项、页眉串入正文 | **不处理**，只标记给人工 |

### 1.2 三条铁律

1. **不猜内容**。任何"没有唯一确定机械改法"的情况一律保持原样或报错。
2. **只改格式 token**。正文语义字符不得新增或丢失（实测用汉字守恒做验收）。
3. **原始文件只读**。所有产物写新文件；批处理脚本也从不改输入。

### 1.3 三个工具，零代码耦合

```text
PDF ──(pdf2md.py)──> 同名 .md（与 PDF 同目录）
                        │
                        ├──(md-math-normalizer)──> <同名>.规范化.md
                        └──(ocr_mark.py)────────> 可疑行报告（stdout）
```

它们之间只有**文件契约**：产物是磁盘上的 `.md`，没有共享代码、没有互相导入、没有网络调用。任一段都可以单独替换或跳过。

## 2. 数据流与目录约定

### 2.1 输入类型与输出位置

| 输入 | 处理 | 输出 |
| --- | --- | --- |
| `X.pdf` | OCR | `X.md`（同目录）；`--keep-images` 时 `X_media/` |
| `X.md` | 跳过 OCR | `X.规范化.md`（同目录） |
| 目录 | 只取**直接子级**的 `.pdf`/`.md` | 各自同目录 |

**不进子目录**是硬规则：`D:\Docs` 会处理 `D:\Docs\1.pdf`，不会处理 `D:\Docs\1\2.pdf`。

### 2.2 编码与换行

- 输入按 UTF-8 读，识别并**保留 BOM**（`utf-8-sig`）。
- 识别主要换行风格（LF / CRLF）并**原样输出**，不因处理而改变。
- 写文件走**原子替换**：临时文件 → `fsync` → `os.replace`，`--in-place` 不会边处理边覆盖。

## 3. 第一段：`pdf2md.py`

### 3.1 执行顺序

```text
① collect_pdfs()        展开输入（目录只取直接子级，按 resolve() 去重）
② resolve_token()       令牌：--token → 进程环境变量 → 用户级注册表
③ create_inference()    provider=aistudio, model=PaddleOCR-VL-1.6
④ _predict_with_retry() 配额/排队错误退避重试
⑤ normalize_block_math() 去每行行尾空白
⑥ write_media()         --keep-images 时落盘图片（含格式校验与下载重试）
⑦ rewrite_image_sources() 只改 img 的 src 取值
⑧ find_broken_image_sources() 仍是远端 URL 的逐条告警
```

### 3.2 为什么令牌要查注册表

刚设置的用户级环境变量不会进入**已经在运行**的进程。脚本因此在进程环境缺失时直接读 `HKCU\Environment`，避免"明明设了却说没设"。

### 3.3 图片处理的三条约束

| 约束 | 原因 |
| --- | --- |
| 下载失败退避重试 3 次（2s→4s→8s） | 图片托管在 CDN，偶发 SSL 抖动很常见 |
| 落盘前按**文件头**校验格式 | AI Studio 返回的是**图片 URL**（本地推理返回 base64），两种负载都可能失效；不校验会写出 218 字节的坏文件 |
| 下载失败的引用**保留远端 URL 并告警** | 绝不能把引用改成不存在的本地路径 |

图片键可能带子目录（`imgs/xxx.jpg`），落盘时**原样保留目录结构**，否则 markdown 里的相对路径会失效。

### 3.4 块级公式的行尾空白

OCR 输出 `  $$ ... $$ `（前后带空格）。行尾空格会让标准 Markdown 渲染器认不出 `$$` 块，因此去掉**每行行尾空白**。公式内容一律不动。

## 4. 第二段：规范化器（核心）

### 4.1 总控：跑两次并比较

```python
normalize_pipeline(text):
    first  = _normalize_once(text)
    second = _normalize_once(first.text)
    if first.text != second.text: raise ValidationError(idempotence)
```

幂等是硬要求：第二次运行必须不再产生任何变化。这既是正确性保证，也防止规则之间互相打架。

### 4.2 单次的 7 个阶段（顺序不可换）

```text
⓪ 保护扫描 + 定界符解析
① 字符标准化
② 重新扫描全部 span
③ 裸数学入环境（掩码 + 候选扫描 + 包装）
④ 下划线空白替换
⑤ 数学环境合并（循环到不动点）
⑥ \displaystyle
⑦ 从零重新验证
```

### 4.3 ⓪ 保护扫描：必须最先做

`<img src="https://a.com/b_1.png" width="50%">` 里有 `=` `/` `:` `%` `_` 和数字。若先做数学化，HTML 直接被毁。

识别顺序（每步跳过已被覆盖区域）：

```text
1. fenced code   ``` / ~~~（含未闭合，保护到文末）
2. inline code   `...`
3. raw HTML      <div> <img> …（整标签含属性）
4. URL           https?:// ftp://
5. markdown 链接与图片  [文字](目标) / ![图](目标)
6. autolink      <https://...>
7. 转义序列      \ + ASCII 标点（连续 3 组以上 \_ 除外，留给空白替换）
```

最后**嵌套只保留最外层**——链接里的 URL 不再单独登记，否则 protected 校验会误报"内容丢失"。

同时解析已有定界符：

```text
$ → 看下一个字符是否也是 $ → 最长匹配 $$ 优先
跳过 \$（按连续反斜杠奇偶性）
跳过 protected 内的 $
环境内部再现未转义 $ → ERROR_NESTED_MATH_ENVIRONMENT
无配对 → ERROR_UNBALANCED_INLINE_MATH / _DISPLAY_MATH
```

**有解析错误立即中止**：在改动任何字符之前就报出来。

### 4.4 ① 字符标准化：只替换明确列出的字符

对非 protected、非数学环境区域逐段做三件事：

```text
1. "……" → "…"（先合并，避免逐字映射成 "... ..."）
2. str.translate(CHARACTER_TRANSLATION)   逐字符查表
3. 标点补空格
```

映射表**只含两类**（这是"不越界"的关键）：

| 类别 | 例子 |
| --- | --- |
| 全角 ASCII 变体 U+FF01–FF5D | `ＡＢＣ１２３`→`ABC123`、`（`→`(` |
| 明确列出的中文标点 + 非 CJK/非数学数字形式的兼容分解 | `，`→`,`、`、`→`,`、`。`→`.`、`“`→`"`、`【`→`[`、`……`→`...` |

**明确不映射**（改了就是破坏数学内容）：`π ≤ √ ∈ × ∞ ⊆`、上标下标 `² ₁`、带圈数字 `①②`、罗马数字 `Ⅰ`、CJK 标点 `《》`。

补空格的规则按此顺序判断（`char == "."` 时）：

```text
1. 后一个是空白或行尾                    → 不补
2. 后一个是 . , ; : ! ?（连续标点）      → 不补
3. 前后都是数字（小数点 3.14）           → 不补
4. 是行首题号的句点（点前只有数字、
   数字前只有空白，如 9.）               → 不补
5. 其余                                  → 补一个空格
```

其余标点 `, : ; ! ?` 后非空白就补一个空格。

**protected 区域逐字节穿过**：按 span 切片拼接，中间片段完全不处理。

### 4.5 ② 重新扫描

字符标准化会改变长度（`，`→`, `、`……`→`...`），旧 offset 全部失效。必须重新跑保护扫描 + 定界符解析，建立最终位置索引。

### 4.6 ③ 裸数学入环境（最复杂的一步）

#### 3.1 掩码：哪些数字**不许**进公式

按此顺序标记（顺序决定优先级）：

```text
1. 题号   ^[ \t]*[0-9]+\.[ \t]*(?=[ \t(（]|[^0-9\s])   → 数字与句点
2. 分值   [(（]?[0-9]+(?=分)                            → 数字
3. 编号标签 NUMBERING_MARKER_RES
```

编号标签四类：

| 模式 | 覆盖 | 例子 | 备注 |
| --- | --- | --- | --- |
| 选项标记 | `(A)` `（D）` | `(A) 关于 x 轴对称 (B) …` | **限大写**，不限行首；`(x)` 是函数记号不能误伤 |
| 行首编号 | 允许前置 `###`/`-`；数字后跟 `.` `、` `)` `）` 或空白 | `### 1.`、`1.`、`(2)`、`（10）`、`1 函数…` | |
| 标签前缀 | 例/题/图/表/式/注/第 + 数字 | `例1`、`例 10`、`第3节`、`图2-1` | |
| 圈码罗马 | `①`–`⑳`、`Ⅰ`–`ⅿ` | `①当 x>1 时` | |

> **规格偏离说明**：规格 §50 原文是"除题号、分值外不存在其他数字例外"。编号标签是用户明确要求的额外例外——编号是版面标签，`例$1$` 只是噪音。这条偏离写在 `config.py` 注释里，并由 `tests/test_numbering_labels.py` 锁定。

#### 3.2 候选扫描

先把文本按 blocked（已有数学环境 + protected）切成区间，区间内逐字符判定：

```text
命中掩码                    → 否
\r \n                       → 否（换行是硬边界）
CJK 汉字                    → 否（汉字是强边界）
$                           → 否（不许吞已有环境）
结构字符 `* _ ~ [ ] ( ) ! < > | #`（去掉 _ 后）→ 否
? ! 等跳过标点              → 否
.                           → 仅当**前后都是数字**才算
空格 / 制表                 → 是（数学式内部允许空格）
不可打印                    → 否
其余                        → 是
```

`_ ^ { } \` **不在**结构字符里——`x_1`、`a_{n+1}`、`\frac{a}{b}` 必须整体保留。

对每个连续段做边缘处理：

```text
剥首尾空白 → 剥首尾标点 , . : ; ! ? → 结尾数字后的句点保留（10.）
内容校验：段内至少一个字母数字或反斜杠，否则丢弃
```

最后这条是 `,` 或 `.` 单独成段被排除的原因。

#### 3.3 包装与空白替换

```text
普通段 → "$" + 内容 + "$"
内容以 = 结尾且后面紧跟下划线空白 → 等号留在数学环境外
连续 ≥3 个 _ 或 ≥3 组 \_ → $\underline{\quad\quad\quad}$
```

### 4.7 ⑤ 合并：循环到不动点

每轮找行内环境，检查两两间隙，能合就合，直到一轮无变化。

| 间隙内容 | 处理 |
| --- | --- |
| 空 | 合并 |
| 换行 / 汉字 / Markdown 结构字符 / 反斜杠 / protected 区域 | **阻止** |
| `.!?` 句末标点 | **阻止**（见下） |
| 空白、`+ - = < > ^ / \|`、其余 Unicode 标点 | 允许 |

合并时**间隙原文一字不改**，只去掉中间两个定界符：

```text
$a$ = $b$         → $a = b$
$a$,$b$           → $a,b$
$a$ + $b$ = $10$  → $a + b = 10$
$a$.  $b$         → 不合并
```

> **为什么句末标点必须阻止**：字符标准化给句号补空格后得到 `$ (k \in Z) . `。若把 `". "` 当可合并间隙，就会把句号甚至后面的正文吞进环境：
> `$ (k \in Z) $.  $ y = \cot x $ 在 …` → `$ (k \in Z) .   y = \cot x $ 在 …`
> 这是实测发现的破坏性 bug，已修复并用 `tests/test_merge_period_safety.py` 锁住。

### 4.8 ⑥ `\displaystyle`

只处理行内环境：

```text
开头（跳过前导空白）已是 \displaystyle → 原样（防重复）
含 \frac \dfrac \cfrac \sum \prod \coprod \int \iint \iiint \iiiint
   \oint \bigcup \bigcap \bigsqcup \bigvee \bigwedge \bigoplus
   \bigotimes \bigodot
   → 在内容最前插入 "\displaystyle "
块级 $$...$$ → 完全不处理
```

只改这一个位置，内容其余部分（含尾随空白）逐字保留。

### 4.9 ⑦ 验证：不信任何前置模块

从零重新扫描，按顺序检查：

```text
1. 定界符解析诊断          → has_fatal_error
2. 裸数学残留               ERROR_UNWRAPPED_MATH
3. 仍可合并的环境           ERROR_MERGEABLE_INLINE_MATH
4. 重复 / 缺失 displaystyle ERROR_DUPLICATE_DISPLAYSTYLE / _MISSING_
5. 题号被包进数学环境       ERROR_QUESTION_NUMBER_MATHIFIED
6. 分值被包进数学环境       ERROR_SCORE_MATHIFIED
7. protected 片段被改动     ERROR_PROTECTED_CHANGED
8. 固定点检查               跑两遍，first == second == text
```

`CheckResult` 字段与退出码：

| 字段 | 含义 | CLI 退出码 |
| --- | --- | --- |
| `is_valid` | 已是规范形式（固定点） | 0 |
| `needs_normalization` | 需要改且可安全自动完成 | 1 |
| `has_fatal_error` | 无法安全处理 | 2 |

**循环依赖的解法**：validator 需要问"是否规范"，而判断方式是跑管线；管线末尾又要调 validator。因此 validator 直接调 `_normalize_once(validate=False)`（只变换、不回头验证），两个模块永不递归。

## 5. 第三段：`ocr_mark.py`（只标记）

逐行跑五条规则，命中即记录，**绝不写文件**：

| 规则 | 判定 | 例子 |
| --- | --- | --- |
| R1 | 整行像「页码 + 书名」且行内无 `$` | `1 三角函数的图象与性质`、`___ 1 三角函数的图象与性质` |
| R2 | 标题里 CJK 之间夹空格 | `## 三 角函数` |
| R3 | 标题以解题语气词开头 | `## 分析 正确理解所给等式…` |
| R4 | 引用名字含 `header` 的图片 | `<img src="imgs/img_in_header_…">` |
| R5 | 空标题 | 只有一个 `#` |

R1 的书名取自文中标题行做比对。退出码 `0` 无可疑 / `1` 待确认 / `2` 输入错误。

> **为什么只标记不删**：判断"这行是页眉还是正文"需要版面上下文，纯本地规则无法可靠区分；误删正文的代价远大于留噪音。规格也要求本工具不得依赖模型能力，所以不做猜测式删除。

## 6. 第四段：`run_pipeline.py`（批处理编排）

### 6.1 单输入的五个步骤

```text
[1/4] OCR        PDF → .md（.md 输入则跳过）
[2/4] 体检       --check，得到 0/1/2
[3/4] 规范化     -o <同名>.规范化.md（原文件不动）
[4/4] 复检       对规范化结果再 --check，必须为 0
[标记] 可疑行    ocr_mark，只报告
```

任何一步失败只影响该项，继续处理后面的输入。

### 6.2 输入展开规则

```text
文件  → 按后缀收下（只认 .pdf/.md）
目录  → 只取直接子级的 .pdf/.md
去重  → 按 resolve() 小写去重（同一文件传两次只处理一次）
排除  → * .规范化.md 不作为输入，避免自我循环
```

### 6.3 拖拽用法

把任意多个文件/文件夹**拖到 `运行全流程.cmd` 上**即可。脚本用 `chcp 65001` 保证中文输出，结束时等待按键以免窗口闪退（脚本化调用加 `--no-pause`）。

`run_pipeline.py` 按**相对位置**定位规范化器（同级目录 `../md-math-normalizer`），也支持用
`MD_MATH_NORMALIZER` 环境变量覆盖。调用规范化器时优先用 `<venv>/python -m md_math_normalizer`：
pip 生成的 `.exe` 启动器在项目被移动后可能失效，`-m` 形式稳定。

### 6.4 多 PDF 并发入口（`run_pipeline_parallel.py`）

**任务粒度**：一个 PDF = 一个完整独立的 worker 任务（输入 PDF → OCR → 规范化 → 复检 → 标记），
**不并发化单个 PDF 内部的阶段**。并发只存在于不同 PDF 的完整任务之间。

```text
父进程（调度器）
├── 子进程 A：run_pipeline.py A.pdf   ← 内部完全串行
├── 子进程 B：run_pipeline.py B.pdf   ← 内部完全串行
└── （任一结束才补下一个）
```

| 设计点 | 实现 |
| --- | --- |
| 并发单元 | 独立操作系统进程（`subprocess.Popen`），不用线程池/进程池调内部函数 |
| 并发上限 | `--workers N`，默认 **2**（不按 CPU 核数自动放大——瓶颈是远端 OCR 服务） |
| 有界调度 | 待处理队列 + `active` 字典（长度恒 `≤ workers`）；一个结束才补一个 |
| 输入范围 | 只接受 `.pdf`；目录只取直接子级；`resolve()` + 大小写归一 + 去重 |
| 复用入口 | worker 命令 = `<python> run_pipeline.py "<pdf>" --no-pause [...]`，不复制其逻辑 |
| 失败隔离 | 单 PDF 失败只标记该任务；全局性问题（入口/解释器缺失、参数非法）才整体返回 2 |
| 日志隔离 | 每个 worker 独立 `PIPE` 捕获 stdout/stderr；成功只打一行状态，失败才输出该任务日志 |
| Ctrl+C | 清空队列（不再启动）→ 终止所有运行中的 worker（Windows 用 `taskkill /F /T`）→ 返回 130 |
| 不写文件 | 调度器不打开/写/删任何文件；产物全部由原 pipeline 的原子写入负责 |
| 无重试层 | 不整条重跑失败的 PDF（避免与 OCR 自身重试、图片下载重试叠加成 retry storm） |

顺序规则：文件参数保留传入顺序、目录展开按名字排序，两者都确定，因此汇总列表可复现。

**结果一致性**：`--workers 1` 构造出的 worker 命令与直接调用 `run_pipeline.py` 逐字相同；
多个 PDF 并发时，每个 PDF 的产物与串行单独执行逐字节一致（已用假 worker 实测验证）。

#### 6.4.1 自适应限流：跟着远端压力调整**提交速度**

远端 OCR 是共享配额服务，`--workers` 是**上限**而非保证值。所以调度器不用固定速率提交，
而是根据 worker 的真实报错动态调整"还发不发下一个"：

| 设计点 | 实现 |
| --- | --- |
| 压力识别 | `remote_pressure.classify_failure()` 对 `stdout + "\n" + stderr` 全文匹配：错误码 `10010`、`HTTP 429` / `HTTP 503` / `HTTP 504`、`queue_full` / `rate_limit` 文本 |
| 全局冷却 | 命中后暂停**启动新 worker**，时长按级数取 `COOLDOWN_STEPS = (5, 10, 20, 40, 60)` 秒 |
| 运行中不打断 | 冷却只作用于提交闸门；已在跑的 worker 继续跑完，不 kill、不降并发数 |
| 渐进恢复 | 每次成功 `level -= 1`（不是清零），冷却相应回退一级 |
| 提交间隔 | `--launch-interval`（默认 `0.5s`）保证两次启动之间有最小间隔，避免同刻突发 |
| 额度耗尽 | `今日提交任务已达上限` 判为 `QUOTA_EXHAUSTED`：**不冷却、不计入背压**，只如实报告（重试无用） |
| 冷却期不丢任务 | 循环条件为 `while pending or active`：即使冷却把 `active` 清空，也会先等冷却再补位 |
| 每 PDF 只跑一次 | 冷却只是**延后启动**，任务始终留在 `pending`；全程不重跑任何已启动的 PDF pipeline |
| 可测的时钟 | `run_bounded(clock=, wait_any=, launch_worker=)` 全部可注入；测试用虚拟时钟，不真 sleep |

失败分类（`failure_kind`）：`REMOTE_BACKPRESSURE` / `QUOTA_EXHAUSTED` / `OCR_FAILURE` /
`PIPELINE_FAILURE` / `LOCAL_ENVIRONMENT` / `NONE`，汇总时逐条打印，便于判断"该重跑"还是"该等配额"。

`--workers > 4` 只给一行告警（提示远端会限流），不阻塞执行。

## 7. 决策记录（为什么这样设计）

| 决策 | 理由 | 备选方案与否决原因 |
| --- | --- | --- |
| 保护扫描放在字符处理前 | 否则 HTML/URL 会被数学化 | —— |
| 字符标准化后重新扫描 | 长度变化导致 offset 失效 | 维护 offset 映射：实现复杂、易错 |
| 合并循环到不动点 | 相邻多段公式要一次合并完 | 单轮合并会留下可继续合并的残留 |
| 句末标点阻止合并 | 修复吞正文的破坏性 bug | 只按标点判定：会吞正文 |
| 嵌套判定只看"环境内有 `$`" | 曾用"错位收尾符"启发式，实测误报 299 处；OCR 宽松写法本身合法 | 保留启发式：持续过拟合、不断冒新误报 |
| 编号标签保持原样 | 用户明确要求；编号是版面标签 | 严格遵守规格 §50：产生 `例$1$` 噪音 |
| 页眉只标记不删 | 无版面上下文无法可靠判定 | 规则删除：可能删掉正文；用模型：规格禁止 |
| OCR 工具独立于智能体 | 用户要求；OCR 是通用能力 | 挂在 DSH/MCP 下：能力被宿主绑定 |
| 图片失败的引用保留远端 | 改成不存在的本地路径更糟 | 静默丢弃：用户不知道图丢了 |
| 并发单元 = 整个 PDF 任务 | 单 PDF 内部阶段有严格顺序（保护→标准化→扫描→合并→displaystyle→验证），并发化会破坏不变量且无收益 | 并发化阶段：正确性风险 + 远端 OCR 才是瓶颈 |
| 并发默认 2、不按 CPU 核数 | 瓶颈是共享的远端 OCR 服务；放大并发只会加剧排队 | `os.cpu_count()`：本机 8–16 核会瞬间打满远端队列 |
| 调度层不做重试 | 已有 OCR 网络重试 + 图片下载重试，再叠一层会形成 retry storm | 自动重跑失败项：重复远端请求、放大配额消耗 |
| 限流时只闸"新提交" | 运行中的 worker 已花掉配额，杀掉只会白费；真正要控的是**提交速率** | 动态降 workers/kill 子进程：浪费已完成的工作，且无助于已提交的任务 |
| 冷却 5→10→20→40→60 | 远端恢复时间不确定，指数退避能快速让出通道 | 固定 sleep：要么太短继续撞墙，要么太长拖慢整体 |
| 恢复是 `level -= 1` 而非清零 | 刚恢复就满速提交会立刻二次限流，形成锯齿 | 成功即清零：反复触发冷却，吞吐反而更低 |
| 额度耗尽不冷却 | 每日配额用尽重试无用，冷却只是浪费时间 | 与临时限流同处理：白等 60s×N 且掩盖真实原因 |

**当前：154 项全通过。**

### 8.2 端到端（真实 20 页文件）

```text
pdf2md    20 页，6/6 图落盘，块级公式行尾空格 41→0，远端 URL 残留 0
--check   原 .md             exit 1（可安全修复）
-o        .md → .规范化.md    exit 0
--check   .规范化.md          exit 0（已规范）
幂等      再规范化一次         字节完全一致
守恒      汉字 4584 → 4584；中文标点残留 0
ocr_mark  原 .md             7 处可疑行，与人工通读完全一致
```

### 8.3 每次改规则后的必做检查

1. `pytest` 全绿（不许删测试、不许放宽断言）。
2. 真实文件重跑一遍，确认**汉字数守恒**、**中文标点残留为 0**。
3. 确认幂等：`--check` 规范化结果必须 exit 0。
4. 若改了合并或候选规则，额外确认没有正文被吞进数学环境（`$$...$$` 与 `$...$` 内不得出现汉字）。

## 9. 已知限制与后续

| 限制 | 说明 | 影响 |
| --- | --- | --- |
| AI Studio 是共享服务 | 高峰期返回"任务提交队列已满" | 已退避重试；大批量建议错峰 |
| 页眉判断靠规则 | 未收录的页眉形态可能漏报 | 漏报可接受（人工看报告），误报已尽量压低 |
| 宽松公式形态保留 | `$ y = \sin x $` 不会变成 `$y=\sin x$` | 按用户要求；渲染无碍 |
| 编号标签规则是白名单 | 未收录的编号形态（如 `附1`）仍会被数学化 | 需要时在 `NUMBERING_MARKER_RES` 加一条 |
| 不做数学内容纠错 | `sum` 不会变 `\sum` | 设计如此，规格要求 |
