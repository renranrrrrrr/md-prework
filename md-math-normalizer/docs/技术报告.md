## 1. 项目背景与问题定义

### 1.1 输入的现实形态

输入是 OCR（PaddleOCR-VL）产出的中文数学 Markdown。它的典型特征：

```text
1. 公式一律带空格：  正弦函数  $ y = \sin x $ 和正切函数  $ y = \tan x $、余切函数 …
2. 中文标点为主：    ，。 ：； （） “”
3. 块级公式带尾空格：  $$ -\tan x-1\geqslant0, $$
4. 编号是纯文本：    1.  (2)  ①  例1   ### 1.
5. 混入版面残留：    1 三角函数的图象与性质   /   ## 三 角函数
6. 图片是 HTML：     <div style="text-align:center;"><img src="..."></div>
```

### 1.2 问题的可分性

| 类别 | 是否可机械判定 | 处理方 |
| --- | --- | --- |
| 字符编码/标点 | 是（有唯一 ASCII 等价形式） | 规范化器自动化 |
| 裸数学是否该入环境 | 是（字符类别判定） | 规范化器自动化 |
| 该不该合并两个环境 | 是（间隙内容判定） | 规范化器自动化 |
| 该不该加 `\displaystyle` | 是（命令白名单） | 规范化器自动化 |
| OCR 认错符号 / 公式缺项 | **否**（无唯一解） | 不处理，只标记 |
| 某行是页眉还是正文 | **否**（需版面上下文） | 不处理，只标记 |

这条分界线是整个设计的基石：**可机械判定的自动化，不可判定的交人工并明确报告**。

### 1.3 三条设计铁律

1. **不猜内容**：没有唯一确定机械改法的情况，保持原样或报错。
2. **只改格式 token**：正文语义字符不得新增或丢失。验收时用**汉字守恒计数**量化检查。
3. **原始文件只读**：所有产物写新文件；`--in-place` 也走原子替换，绝不边读边写。

### 3.1 规则集中化（`config.py`，208 行）

所有确定性规则集中在**唯一来源**，禁止散落：

| 常量 | 规模 | 作用 |
| --- | --- | --- |
| `ASCII_PUNCTUATION_MAP` | 58 条 | 明确列出的中文标点 → ASCII |
| `ASCII_COMPAT_MAP` | 429 条 | 程序生成：全角 ASCII 变体 + 非 CJK/非数学数字形式的兼容分解 |
| `CHARACTER_MAP` | 471 条 | 合并后的最终映射表 |
| `DISPLAYSTYLE_COMMANDS` | 19 条 | 需要 `\displaystyle` 的大算符白名单 |
| `NUMBERING_MARKER_RES` | 4 条 | 编号标签正则 |
| `QUESTION_NUMBER_RE` / `SCORE_RE` | — | 题号 / 分值 |
| `MARKDOWN_BOUNDARY_CHARS` | 13 字符 | 数学候选不得跨越的结构字符 |

`ASCII_COMPAT_MAP` 的生成策略——**只保留唯一且无损的等价形式**：

```python
def _build_ascii_compat_map():
    for point in range(sys.maxunicode + 1):
        char = chr(point)
        if point < 0x80:                       continue
        if category in {"Cc","Cs","Co","Cn"}:  continue
        if _is_fullwidth_ascii_variant(char):  # U+FF01–FF5D
            mapping[char] = chr(point - 0xFEE0)   # 全角→ASCII，唯一无损
            continue
        if _is_cjk_char(char) or _is_math_or_number_form(char, point):
            continue                            # ★ 关键排除
        decomposed = unicodedata.normalize("NFKC", char)
        if all(ord(c) < 0x80 for c in decomposed) and decomposed != char:
            mapping[char] = decomposed
```

**★ 关键排除**的覆盖面，是"不破坏数学内容"的实现保证：

```python
0x2070–0x209F  上标下标     ² ₁        ← 数学含义
0x2150–0x218F  数字形式/罗马 ⅓ Ⅰ        ← 数学含义
0x2460–0x24FF  带圈字母数字  ①②        ← 编号含义
0x2100–0x214F  字母式符号    ℕ ℝ        ← 数学含义
0x1D400–0x1D7FF 数学字母数字
category == "No"  其他数字形式
0x2E80–0x303F   CJK 部首与标点 《》【】  ← 中文排版
0x3040–0x30FF   假名
0x3400–0x9FFF 等 汉字
```

验证：该文件出现的 7 种未映射字符是 `π ① ∞ ② ③ ④ ⊆`——全部是必须保留的数学/编号符号，映射表覆盖度**恰好正确**。

### 3.2 ⓪ 保护区域识别（`protector.py`，196 行）

#### 3.2.1 为什么必须第一步

考虑 `<img src="https://abc.com/a_123.jpg" width="50%">`：里面含 `=` `/` `:` `%` `_`、数字、英文。若先做裸数学包装，这一整段会被包进 `$...$`，HTML 直接毁掉。**保护必须在任何字符处理之前。**

#### 3.2.2 七步识别顺序

```python
def protect_markdown(text):
    spans  = _protect_fenced_code(text)            # 1. ``` / ~~~（含未闭合→保护到文末）
    spans += _protect_inline_code(text, spans)     # 2. `...`（处理转义反引号）
    spans += _protect_html(text, spans)            # 3. <div> <img> 整标签含属性
    spans += _protect_urls(text, spans)            # 4. https?:// ftp://
    spans += _protect_markdown_links(text, spans)  # 5. [文字](目标) ![图](目标)
    spans += _protect_autolinks(text, spans)       # 6. <https://...>
    spans += _protect_escaped_sequences(text,spans)# 7. \ + ASCII 标点
    return _sorted_unique_spans(text, spans)
```

每一步都通过 `is_in_spans()` 跳过已被前面步骤覆盖的区域，避免重复登记。

#### 3.2.3 三个实现细节

**细节 1：URL 字符类必须排除包裹符**

```python
_URL_RE = re.compile(r"\b(?:https?|ftp)://[^\s\]\[<>()\"']+")
```

若不排除 `<>()`，`<div>https://a.com/b.png</div>` 里的 URL 会吞掉 `</div>`。

**细节 2：HTML 与 URL 重叠时的 kind 归属**

`_sorted_unique_spans()` 只保留最外层 span，但 kind 选择有个陷阱：先收集"所有原始 span 中出现过的具体 kind"，再挑选。

```python
def _pick_kind(kinds):
    for kind in kinds:
        if kind is not ProtectedKind.RAW_HTML:
            return kind            # RAW_HTML 是兜底
    return kinds[0]
```

效果：`<div>URL</div>` → 登记 `RAW_HTML(0,5) + URL(5,30) + RAW_HTML(30,36)`，最外层 kind 为 `RAW_HTML`（因为 cluster 含两个 HTML）；`<img src="URL">` → 最外层 kind 为 `URL`。测试 `test_html_and_urls_protected` 要求两种 kind 都可见。

**细节 3：嵌套 span 导致校验误报**

Markdown 链接 `[链接](https://a.com/r?id=1)` 会同时登记"整链接"和"链接内 URL"两个 span。校验环节按顺序查找 protected 原文片段时，游标会被整链接片段推到 URL 之后，找不到 URL → 误报 `ERROR_PROTECTED_CHANGED`。

解法：校验只比对**最外层**区域：

```python
def _top_level_protected_spans(spans):
    ordered = sorted(spans, key=lambda s: (s.start, -s.end))
    kept = []
    for span in ordered:
        if kept and span.start >= kept[-1].start and span.end <= kept[-1].end:
            continue                      # 被更宽的 span 覆盖
        kept.append(span)
    return tuple(kept)
```

### 3.3 定界符解析（`math_parser.py`，88 行）

#### 3.3.1 扫描逻辑

```python
while i < n:
    跳过非 $ 与 \$（按连续反斜杠奇偶性判断转义）
    跳过 protected 区域内的 $

    if 下一个字符也是 $:                      # 最长匹配原则
        向前找配对的 $$ → DISPLAY_MATH span
        环境内部出现未转义 $ → ERROR_NESTED_MATH_ENVIRONMENT
        找不到 → ERROR_UNBALANCED_DISPLAY_MATH
    else:
        向前找配对的 $
        环境内部出现未转义 $ → ERROR_NESTED_MATH_ENVIRONMENT
        找不到 → ERROR_UNBALANCED_INLINE_MATH
```

转义判断要处理**连续反斜杠奇偶性**：

```python
def is_escaped(text, offset):
    backslashes = 0
    i = offset - 1
    while i >= 0 and text[i] == "\\":
        backslashes += 1; i -= 1
    return backslashes % 2 == 1
```

#### 3.3.2 嵌套判定：只保留一条原则

早期实现用了"收尾分隔符放错位置"的启发式（`$a $b$ c$` 这类形态），但在真实 OCR 文件上**误报 299 处**。原因：OCR 的宽松写法里，两个 `$` 之间可能全是正文（`$1$` 到下一个 `$` 之间是 `. 三角函数性质\r\n\r\n奇偶性: 正弦函数  `），任何"看内容"的判据都会误判。

**最终实现**：嵌套只按一条可验证的原则判定——**已配对的环境内部又出现未转义的 `$`**：

```python
def _has_embedded_dollar(content):
    for index, char in enumerate(content):
        if char == "$" and not is_escaped(content, index):
            return True
    return False
```

同时确认：`$a $b$ c$` 其实解析成 `$a $` 与 `$ c$` **两个完整配对**的环境，不是畸形——这与"保留 OCR 宽松形态"的要求一致。

### 3.4 ① 字符标准化（`char_normalizer.py`，117 行）

#### 3.4.1 三步处理

```python
def _normalize_unprotected(text):
    collapsed = text.replace("……", "…")                       # 1. 先合并省略号
    mapped    = collapsed.translate(CHARACTER_TRANSLATION)    # 2. 逐字符查表
    return _ensure_punctuation_spacing(mapped)                # 3. 标点补空格
```

第 1 步的顺序有原因：`……` 若逐字映射会变成 `... ...`（两个映射结果拼接）。

#### 3.4.2 句点补空格的四条例外（顺序敏感）

```python
def _needs_space_after_period(text, index):
    next_char = text[index + 1] if index + 1 < len(text) else ""
    if next_char == "" or next_char.isspace():               # ① 句末
        return False
    if next_char in ".,;:!?":                                # ② 连续标点
        return False
    if text[index-1].isdigit() and next_char.isdigit():      # ③ 小数点 3.14
        return False
    if _is_question_number_period(text, index):              # ④ 行首题号 9.
        return False
    return True
```

第 ④ 条是 OCR 场景的关键：`9.（16分）` 若补空格会变成 `9. (16分)`，题号与分值被拆开。判定实现是"点前必须是数字，且数字之前只允许空白或行首"：

```python
def _is_question_number_period(text, index):
    position = index - 1
    digits = 0
    while position >= 0 and text[position].isdigit():
        digits += 1; position -= 1
    if digits == 0:
        return False
    while position >= 0:                    # 数字之前只允许空白
        if text[position] == "\n":  return True
        if not text[position].isspace(): return False
        position -= 1
    return True
```

这样 `结果为 10.` 的句点会补空格（前面有"为"，非行首），而 `9.（16分）` 不会。

#### 3.4.3 protected 区域逐字节穿过

```python
def normalize_text(text, protected_spans=()):
    pieces = []; cursor = 0
    for span in protected_spans:
        start = max(cursor, min(len(text), span.start))
        end   = max(start,  min(len(text), span.end))
        pieces.append(_normalize_unprotected(text[cursor:start]))  # 处理间隙
        pieces.append(text[start:end])                            # 原样穿过
        cursor = end
    pieces.append(_normalize_unprotected(text[cursor:]))
    return "".join(pieces)
```

### 3.5 ③ 裸数学入环境（`math_candidate.py`，263 行）

这是最复杂的一步，分四个子环节。

#### 3.5.1 掩码：哪些数字不许进公式

```python
def _build_no_math_mask(text) -> list[bool]:
    mask = [False] * len(text)
    # 1. 题号 ^[ \t]*[0-9]+\.[ \t]*(?=[ \t(（]|[^0-9\s])
    # 2. 分值 [(（]?[0-9]+(?=分)
    # 3. 编号标签 NUMBERING_MARKER_RES（四类）
    return mask
```

编号标签四类模式与其实现要点：

| 模式 | 正则要点 | 例子 |
| --- | --- | --- |
| 选项标记 | `[(（](?P<option>[A-Z])[)）]` —— **限大写** + **不限行首** | `(A) … (B) …`；`(x)` 是函数记号不能误伤 |
| 行首编号 | `(?m)^[^\w\n]*?(?:…\|(?P<num>[0-9]+)(?=[.、)）][ \t]\|[ \t]\|$))` —— 允许前置 `###`/`-` | `### 1.`、`1.`、`(2)`、`（10）`、`1 函数…` |
| 标签前缀 | `[例题图表式注第]\s*(?P<num>[0-9]+(?:[.\-][0-9]+)*)` | `例1`、`例 10`、`第3节`、`图2-1` |
| 圈码罗马 | `(?P<num>[\u2460-\u2473\u2160-\u217F])` | `①当 x>1 时` |

**这是对规格的有意偏离**（规格 §50 原文为"除题号、分值外不存在其他数字例外"）。理由：编号是版面标签，`例$1$` 只是噪音。偏离写在代码注释里，并由 `tests/test_numbering_labels.py` 锁定。

#### 3.5.2 候选字符判定

```python
def _is_math_candidate_char(text, index, mask):
    ch = text[index]
    if mask[index]:                 return False   # 编号/题号/分值
    if ch in "\r\n":                return False   # 换行是硬边界
    if is_cjk_ideograph(ch):        return False   # 汉字是强边界
    if ch == "$":                   return False   # 不许吞已有环境
    if ch in _STRUCTURE_CHARS:      return False   # ` * ~ [ ] ( ) ! < > | #
    if ch in _SKIPPED_PUNCTUATION:  return False   # ? !
    if ch == ".":                                  # 只有小数点是数学内容
        return text[index-1].isdigit() and text[index+1].isdigit()
    if ch.isspace():                return ch in {" ", "\t", "\u00a0"}
    if not ch.isprintable():        return False
    return True
```

`is_cjk_ideograph()` 覆盖 CJK 统一表意文字的多段区（含扩展 B–G 与兼容区），不是只用 `\u4e00-\u9fff`：

```python
0x3400-0x4DBF, 0x4E00-0x9FFF, 0x20000-0x2A6DF, 0x2A700-0x2B73F,
0x2B740-0x2B81F, 0x2B820-0x2CEAF, 0x2CEB0-0x2EBEF, 0x30000-0x3134F
```

**注意 `_ ^ { } \` 不在结构字符里**——这是 D1 修复的核心：`x_1`、`a_{n+1}`、`\frac{a}{b}`、`sum_{i=1}^n a_i` 必须作为**同一个**候选整体保留。

#### 3.5.3 区间切分与边缘处理

先把文本按 blocked（已有数学环境 + protected）切成区间，再逐区间扫描；每个连续段做边缘修剪：

```python
def _trim_edges(text, start, end):
    剥首尾空白
    剥首尾标点 , . : ; ! ?
    剥结尾句点时，若前一个字符是数字则保留（10.）
    return start, end

def _is_content_candidate(text, start, end):
    # 段内至少要有一个字母数字或反斜杠，否则丢弃
    return any(text[i].isalnum() or text[i] == "\\" for i in range(start, end))
```

最后这条是 `,` `.` 单独成段被排除的实现。

#### 3.5.4 包装与空白替换

```python

if candidate_content.rstrip().endswith("=") and blank_after:
    out.append("$" + left_content + "$" + operator)

    if char in _SENTENCE_PUNCTUATION: return True  # . ! ? ← 关键
    if is_cjk_ideograph(char):      return True    # 汉字强边界

    if char.isspace():              return False   # 空白允许
    if char in _MERGEABLE_OPERATORS:return False   # + - = < > ^ / |

#### 3.6.3 句末标点必须阻止合并（本轮修复的破坏性 bug）

```text

出错   $ (k \in \mathbf{Z}) .   y = \cot x $ 在 上为减函数     ← 句号 + 下一公式被吞
```

因为 `.!?` 后面必然跟空格，把它们加入阻止集合就同时挡住了这个 bug，且不影响 `$a$ = $b$`（空格 + `=` 仍允许）。已由 `tests/test_merge_period_safety.py` 锁定：

```python
def _normalize_once(text, *, validate=True):
    # ⓪ 保护 + 解析
    first_protected = protect_markdown(text)
    original_snippets = tuple(text[s.start:s.end] for s in _top_level_protected_spans(first_protected))
    existing_math, diags = parse_math_spans(text, first_protected)
    if diags: raise ValidationError(...)                 # 定界符非法 → 立即失败

    # ① 字符标准化（protected 区域与已有数学环境都保护起来）
    normalization_protected = sorted((*first_protected, *existing_math))
    normalized = normalize_text(text, normalization_protected)

    # ② 重新扫描（位置已变）
    final_protected = protect_markdown(normalized)
    math_spans, diags = parse_math_spans(normalized, final_protected)
    if diags: raise ValidationError(...)

    # ③ 裸数学入环境
    with_candidates = wrap_math_candidates(normalized, math_spans, final_protected)
    candidate_protected = protect_markdown(with_candidates)
    candidate_math, diags = parse_math_spans(with_candidates, candidate_protected)
    if diags: raise ValidationError(...)

    # ④⑤⑥ 空白替换 → 合并 → displaystyle
    with_blanks = replace_underscore_blanks(with_candidates, candidate_math, candidate_protected)
    merged = merge_inline_math(with_blanks)
    styled = apply_displaystyle(merged)

    if not validate: return PipelineResult(styled, ())

    # ⑦ 验证
    validation = validate_markdown_text(styled, original_protected_snippets=original_snippets)
    if not validation.is_valid: raise ValidationError(...)
    return PipelineResult(styled, validation.diagnostics)


def normalize_pipeline(text, *, strict=True):
    first  = _normalize_once(text, validate=strict)
    second = _normalize_once(first.text, validate=strict)
    if first.text != second.text:
        raise ValidationError("idempotence ...")         # 幂等是硬要求
    return first
```

**顺序不可换的三处硬约束**：

1. 保护必须在字符处理之前（否则 HTML/URL 被数学化）。
2. 字符标准化之后必须重新扫描（`，`→`, ` 改变长度，旧 offset 失效）。
3. 合并必须在 displaystyle 之前（先合并才知道哪些环境含大算符）。

## 7. 本轮修复的缺陷清单

| # | 缺陷 | 根因 | 修法 | 影响面 |
| --- | --- | --- | --- | --- |
| 1 | 下标/命令被拆碎 | `_ ^ { } \` 被当终止边界 | 从结构字符中移除 `_`，候选扫描保留这些字符 | `sum_{i=1}^n a_i` 不再被切成 3 段 |
| 2 | 到处插空格 | `displaystyle` 阶段对所有行内环境补外侧空格 | 删除整个强制空格逻辑；空格只由包装阶段产生 | 输出与规格示例逐字一致 |
| 3 | 该合并不合并 | 空白与所有 Unicode 标点被当中断符（`+`/`=` 是 Sm/Sk 不算标点） | 区分运算符/标点/结构字符 | `$a$ = $b$` → `$a = b$` |
| 4 | 字符映射越界 | 对整个非保护区跑 NFKC | 改为逐字符查表 + 数学数字形式排除 | `π ² ₁ ① Ⅰ` 不再被改写 |
| 5 | `is_valid` 语义偏松 | 违规只记 WARNING 且 `is_valid=True` | 引入 `conforming` / `has_fatal_error`，CLI 退出码由二者判定 | 退出码语义与规格 §9.3 一致 |
| 6 | 非法嵌套漏报 | 只检查环境内部 | 保留"内部有 `$`"这一条原则并删除脆弱启发式 | 误报 299 → 0 |
| 7 | **正文被吞进数学环境** | 句末标点补空格后形成可合并间隙 | `.!?` 加入阻止集合 | 破坏性 bug，已加回归测试 |
| 8 | 编号被数学化 | 规格要求"所有数字进数学环境" | 新增编号标签掩码（4 类模式，有意的规格偏离） | `例$1$` → `例1` |
| 9 | protected 校验误报 | 嵌套 span 导致顺序查找错位 | 只校验最外层区域 | Markdown 链接/图片不再报"内容丢失" |
| 10 | 图片解码错误 | AI Studio 返回 URL，被当 base64 解 | 支持 URL 下载 + 文件头校验 | 218 字节坏文件 → 74.6 KB 真实 JPEG |
| 11 | 图片引用残留远端 | 下载失败后未改写引用 | 退避重试 + 未落盘引用告警 | 远端 URL 残留 0 |
| 12 | `$$` 行尾空格 | OCR 输出自带 | 输出前逐行 `rstrip` | 41 → 0 |

### 其中两次根因判断失误（值得记录）

**误判 1**：以为序号 2 的"多余空格"来自 OCR。实际是 `displaystyle.py` 里的 `_ensure_inline_math_spacing` 主动补的。教训：先定位阶段，再下判断。

**误判 2**：序号 6 的嵌套误报，我先后给出三个根因假设（OCR 宽松空格 → 包装出的单字符环境 → 两个 `$` 之间的正文），前两个都被实测否定。最终发现真实机制是：`_span_after()` 把"两个 `$` 之间的一切"当公式内容判断，而在 OCR 风格里这段可能是纯正文。教训：**在数据上验证假设，不要在代码上推演**。

## 8. 设计权衡与决策记录

| 决策 | 理由 | 否决的备选方案 |
| --- | --- | --- |
| 保护扫描放在字符处理之前 | 否则 HTML/URL 的 `=` `/` `%` 会被数学化 | —— |
| 字符标准化后重新扫描 | 长度变化使旧 offset 失效 | 维护 offset 映射：实现复杂易错 |
| 合并循环到不动点 | 相邻多段公式需一次合并完 | 单轮合并会留下残留 |
| 句末标点阻止合并 | 修复吞正文的破坏性 bug | 只按"是否标点"判定：会吞正文 |
| 嵌套只按"内部有 `$`" | 启发式实测误报 299 处；OCR 宽松写法本身合法 | 保留"错位收尾符"：持续过拟合 |
| 编号标签保持原样 | 用户要求；编号是版面标签 | 严格守规格 §50：产生噪音 |
| 页眉只标记不删 | 无版面上下文无法可靠判定 | 规则删除（可能删正文）/ 用模型（规格禁止） |
| OCR 工具独立于智能体 | 用户要求；OCR 是通用能力 | 挂在 DSH/MCP：能力被宿主绑定 |
| 图片失败保留远端引用 | 改成坏本地路径更糟 | 静默丢弃：用户不知道图丢 |
| 规范化器保持纯标准库 | 规格 §4；OCR 依赖不进格式化工具 | 直接在规范化器里调 OCR：引入重依赖 |
